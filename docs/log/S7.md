# S7 — Branschlåst presentation och prislista

## Built
- `src/lib/presentation.ts`: `PRESENTATION_BY_CATEGORY` (tabellen i plan §1.11
  literal, typad mot `CATEGORIES`/`THEME_KEYS`), `presentationFor(category)` →
  `{ themeKey, paletteVariant }` och `presentationLabel(category)` → t.ex.
  `servicios · variant 2 (cyan)`. Ren modul: ingen `db`-, React- eller
  Next-import.
- Alla tre skrivvägar härleder nu båda kolumnerna ur branschen och läser
  aldrig ett inskickat värde: `sitios/actions.ts` (skapa + spara),
  `alta/actions.ts` (ersätter uttrycket `category === "otro" ? …`) och
  `alta/[token]/actions.ts` (kunden kan byta bransch mot den förvalda).
- `theme-picker.tsx` är nu `PresentationBlock`: läsbar rad med accentswatch,
  etikett och "Tema och palett följer branschen (plan §1.11)". Uppdateras
  direkt när bransch-selecten ändras, före spar. Inga dolda fält.
- `businessFormSchema` har inte längre `themeKey`/`paletteVariant` — servern
  fyller dem.
- `PLAN_SUGGESTED_PRICE_GS` = 300k / 600k / 900k (§1.13).
- `tests/unit/presentation.test.ts` (9 tester: literal-jämförelse mot §1.11,
  varje bransch → byggt tema, variant 1–4, etiketten) och
  `tests/smoke/presentation.mjs` (17 kontroller).

## Decisions
- **`src/lib/business.ts` rörd utanför fastabellens Owns-kolumn**, enligt
  promptens regel: de två fälten är borttagna ur zod-objektet i stället för
  gjorda valfria — schemat hade annars fortsatt beskriva ett formulärfält som
  inte finns. Inget annat i filen ändrat. (`THEME_LABELS` är därmed oanvänd
  men står kvar; att städa den är inte den här fasens beslut.)
- **`tests/smoke/products.mjs` rörd (S1:s fil, redan mergad).** Den bytte tema
  på business 1 via `select[name=themeKey]` för att få produktsektionen att
  renderas; väljaren finns inte längre, så den byter bransch i stället och
  återställer som förut. Utan ändringen hade `npm run smoke` varit röd, vilket
  är ett exit-kriterium.
- **Röktestet läser preview-URL:en, inte den publika sidan.** Ett utkast får
  inte publiceras utan foton, verifierat nummer och SEO-text; `/preview` kör
  samma `RenderSite` med samma lagrade kolumner.
- **`.t-servicios` finns inte i markupen.** `servicios` är bastemat och dess
  rot är `site-root` utan t-klass (bara comercio/gastronomia/salud lägger till
  en). Röktestet kontrollerar därför "ingen annan t-klass" plus accenten
  `#FF8A1F`, och `t-comercio` + `#0E4E96` efter branschbytet. Att lägga till
  klassen hade krävt en temakatalog, vilket fasen inte får röra.

## Known issues
- Admin-sidorna `nuevo` och `[id]` växer ~7 kB First Load JS (133→140 kB,
  138→145 kB): `isThemeBuilt` drar in temaregistret, och därmed
  temakomponenterna, i klientbunten. Priset betalas av en enda superadmin och
  mekanismen skulle annars försvinna; alternativet är att låta blocket läsa
  `PALETTES` som den gamla väljaren gjorde.
- `BusinessFormDefaults` har kvar `themeKey`/`paletteVariant`. Fälten används
  inte längre av formuläret, men anroparna (`nuevo/page.tsx`, `[id]/page.tsx`)
  ägs inte av den här fasen. Städas av S6 eller en backlog-rad.
- `scripts/seed-dev.ts` sätter variant 1/2/3 för sina tre demorader medan
  tabellen ger 2/1/1. Temat stämmer, varianten inte; seeden är uttryckligen
  utanför fasens omfång. Raderna rättar sig själva första gången de sparas i
  admin.
- Enhetstestet måste stubba temakomponenterna (`vi.mock`) för att kunna läsa
  `BUILT_THEMES`, samma orsak som i `theme-registry.test.ts`: vitest saknar
  JSX-transform för tsconfigs `jsx: "preserve"`.

Verification: typecheck, lint, `npm test` (236/236) och `npm run build` gröna
på 88e357f; `npm run smoke` 5/5 sviter gröna mot MySQL 8.0.46 (färsk migrate +
seed), varav 17 nya kontroller i `presentation.mjs`.
